# Foundry Loadout

Независимый справочник manifest-ссылок для Foundry Virtual Tabletop 13 и 14. Пользователь выбирает версию Foundry VTT, находит модуль, проверяет зависимости и копирует одну закреплённую ссылку.

`Foundry Loadout` пока остаётся рабочим названием. Перед публичным релизом его нужно заменить или согласовать с Foundry Gaming LLC.

## Что уже работает

- отдельные ветки V13 и V14;
- поиск и комбинируемые фильтры;
- четыре модуля с проверенными manifest;
- реальные `minimum`, `verified` и `maximum` без вычисленных границ;
- лицензия и дополнения, которые Foundry VTT предложит установить вместе с модулем;
- premium-карточка без публичной ссылки;
- ручной fallback, если браузер не разрешает копирование;
- статический экспорт для GitHub Pages;
- проверка manifest при каждом запуске CI.

Сайт не устанавливает модули, не собирает очередь и не принимает URL от посетителей.

## Локальный запуск

Нужен Node.js 22.13 или новее.

```bash
npm ci
npm run dev
```

Локальный адрес: `http://localhost:3000/`.

## Проверки

```bash
npm run check
npm run validate:data
```

`npm run check` проверяет TypeScript, линтер, данные, серверный HTML и статический артефакт Pages. `npm run validate:data` обращается к восьми официальным manifest и требует доступ к сети.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает каталог и публикует папку `out/` после push в ветку `master`.

Одно действие владельца репозитория: откройте **Settings → Pages → Build and deployment** и выберите **GitHub Actions** в поле Source.

После этого следующий push в `master` запустит публикацию. Для репозитория `Foundry-Loadout` адрес будет иметь вид `https://<владелец>.github.io/Foundry-Loadout/`.

Если репозиторий переименован, экспорт автоматически берёт новое имя из `GITHUB_REPOSITORY`.

## Данные

Карточки лежат в `data/modules.json`. Обновление считается готовым только после `npm run validate:data`: название или дата релиза сами по себе не доказывают совместимость. Валидатор также сверяет обязательные и рекомендуемые зависимости с `relationships` каждого manifest.

Документы процесса находятся в `docs/pipeline/`, дизайн-система в `design-system/MASTER.md`.
