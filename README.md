# Foundry Loadout

[Каталог модулей Foundry VTT на русском](https://mrmikki-boop.github.io/Foundry-Loadout/): поиск, подборки и ссылки установки для V13 и V14.

Модуль без обязательных зависимостей — копирование одним нажатием. Для остальных сайт показывает порядок установки. Версия Foundry, фильтры и позиция прокрутки сохраняются в браузере. Название карточки и ссылка подборки ведут на постоянный адрес.

## Разработка

Node.js 22.13+:

```sh
npm ci
npm run dev
npm run check
```

`npm run build` собирает статический сайт в `out/`. Карточки включаются в HTML при сборке, поэтому каталог читается без JavaScript. Новые зависимости для этого не нужны.

## Каталог

- `data/modules.json` — названия авторов, описания, версии, источники и зависимости.
- `data/catalog.mjs` — поиск, подборки и порядок установки.
- `data/render.mjs` — карточки, общие для сборки и браузера.
- `app.js`, `index.html`, `styles.css` — интерфейс.

`npm run validate:data` проверяет публичные манифесты по сети: ID, версии, совместимость и зависимости. «Manifest проверен» означает проверку метаданных закреплённого релиза; «Ссылка автора» — обновляемый публичный манифест. Ни один статус не означает проверку в игровом мире. Платные установочные ссылки в каталог не включаются.

У демо и полной версии Laaru один ID: варианты показаны в одной карточке. Classic Facing доступен только в каталоге V14 по текущему манифесту автора.

## Публикация

GitHub Actions проверяет проект и публикует `out/` после push в `master`. В Settings → Pages должен быть выбран GitHub Actions. При смене адреса сайта обновите canonical/Open Graph в `index.html` и `public/sitemap.xml`.

Служебные файлы, кэши, локальные настройки и результаты сборки исключены из Git. Независимый проект, не связан с Foundry Gaming LLC.

## Личные сборки и установочная ссылка

«Моя сборка» хранится отдельно для V13 и V14. Ссылка «Поделиться» содержит ID модулей и версию Foundry; открытие показывает состав и не перезаписывает личную сборку. Это снимок выбора, а не синхронизация между устройствами.

Установочный сервис — `worker/index.mjs`, Cloudflare Worker без базы данных и секретов. Он выдаёт только JSON и ZIP с одним `module.json`; чужие модули скачивает Foundry с сайтов авторов. Произвольные URL сервис не принимает. Платные, неизвестные и недоступные зависимости блокируют выдачу общей ссылки.

Общая ссылка устанавливает технический модуль Foundry Loadout: поле Manifest URL принимает один пакет, а состав сборки указан в `relationships.requires`. Пользователь подтверждает установку зависимостей в Foundry. После проверки наличия всех модулей технический пакет можно удалить; включать его в мире не нужно. Если окно зависимостей не появилось или загрузка не удалась, доступны отдельные ссылки. Сайт проверяет доступность манифеста сборки, но не может подтвердить результат установки в Foundry.

Публикация из корня проекта: `npx wrangler deploy --config wrangler.toml` после входа в Cloudflare. Затем укажите выданный HTTPS-адрес Worker в переменной `VITE_INSTALLER_URL` при сборке сайта и пересоберите сайт. Домен покупать не требуется. Для GitHub Actions добавьте переменную в окружение шага сборки. По умолчанию подключён https://foundry-loadout-installer.foundry-loadout.workers.dev. Переменная VITE_INSTALLER_URL позволяет заменить адрес; пустая строка отключает общую установку.

Vite dev и preview обслуживают тот же обработчик по `/install/` для локальных проверок. Для проверки локального обработчика задайте `VITE_INSTALLER_URL` с адресом локального сервера. Локальная ссылка доступна только на том же компьютере. Проверки: `npm run check`.

Установочная ссылка закреплена за снимком данных каталога. Изменение треков делает старую ссылку недействительной (409), вместо незаметной замены версий. Требуемые версии зависимостей ограничены minimum/maximum. Ссылки авторов могут меняться или исчезнуть; Foundry может потребовать ручной замены уже установленной версии. После установки нужно включить модули и настроить мир. Реальная установка в Foundry V13/V14 должна быть проверена перед публичным запуском сервиса.
