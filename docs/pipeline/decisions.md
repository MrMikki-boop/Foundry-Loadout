# Лог решений

Append-only. Прошлые записи не редактируем.

## 2026-08-19 — Sites/Vinext экспортируется в статический GitHub Pages artifact

**Контекст:** проект должен оставаться сайтом Sites, но пользователь выбрал GitHub как публичный хостинг, а runtime не требует API, БД или секретов.
**Решение:** сохраняем React/Sites/Vinext как сборочный стек и создаём `out/` с base path репозитория для публикации GitHub Actions.
**Альтернативы:** серверный runtime и отдельная база отклонены как лишние; ручная загрузка файлов отклонена из-за невоспроизводимости.
**Последствия:** интерактивность работает только в браузере; перед релизом нужно доказать workflow в GitHub и синхронизировать base path с окончательным именем репозитория.
**Источник:** спайк S-05 и обсуждение с пользователем 2026-08-19.

## 2026-08-19 — Каталог публикует только редакционно проверенные manifest

**Контекст:** совместимость нельзя выводить из названия или даты, `latest` изменяем, а premium manifest может содержать персональный доступ.
**Решение:** одна карточка хранит отдельные закреплённые V13/V14 tracks; публичная ссылка появляется только у `verified`, premium-карточка хранит метаданные и официальную страницу без install/download URL.
**Альтернативы:** пользовательский ввод URL, `latest`, зеркала ZIP и публикация premium manifest отклонены как небезопасные или нарушающие модель доступа.
**Последствия:** новые записи проходят allowlist-валидацию и подтверждаются manifest, релизом и каталогом Foundry VTT; данные требуют регулярной перепроверки.
**Источник:** спайки S-01, S-02, S-03 и S-06.

## 2026-08-19 — Релиз заблокирован до повторного цикла исправлений и аудита

**Контекст:** независимый аудит не нашёл критических product-дефектов, но выявил неполный reserved-IP denylist, дрейф контрактов и отсутствие обязательного Browser QA из-за trusted RPC blocker.
**Решение:** вернуть работу на стадию 7 с T-06 и T-07, затем повторить свежий аудит T-08; не переходить к публикации, пока AC-4 и AC-9 не закрыты.
**Альтернативы:** считать unit/SSR-тесты заменой браузерному проходу и полагаться только на hostname allowlist отклонено: это не выполняет утверждённые acceptance criteria.
**Последствия:** GitHub Pages workflow остаётся подготовленным, но не запускается как релиз до исправлений, выбора публичного имени и явных предрелизных аудитов.
**Источник:** `docs/pipeline/audit.md` от 2026-08-19.

## 2026-08-19 — Контракты описывают только реальные публичные границы

**Контекст:** аудит обнаружил обещанный, но не экспортируемый `copyManifest`, несуществующее поле `finalManifestUrl` и локальный premium-флаг `protected`, которого нет в модели каталога.
**Решение:** публичным API интерфейса остаются функции выборки каталога; Clipboard-обработчик считается внутренней деталью `CatalogApp`. Финальный URL принадлежит результату сетевой проверки `ManifestSnapshot`, а не редакционному `ModuleTrack`. Premium-модель хранит только статус и `null` вместо install/manifest URL; внешний `protected` manifest не копируется в локальную модель.
**Альтернативы:** вводить отдельную библиотеку копирования и дублировать внешний premium-флаг отклонено: это не добавляет пользовательского поведения и создаёт лишнюю публичную поверхность.
**Последствия:** тестируемой сетевой границей служит экспортируемая `validateTrack`; Clipboard success/fallback проверяется на уровне UI, premium-безопасность — тестом каталога.
**Источник:** T-07 и `docs/pipeline/audit.md` от 2026-08-19.

## 2026-08-19 — Metadata и relationships принадлежат конкретной major-ветке

**Контекст:** исследование 28 новых кандидатов показало, что состав систем и зависимостей меняется между V13 и V14; у Levels V13 и V14 разные `relationships.requires`. Официальные protected manifest Hover Distance содержат проверяемые версии и compatibility, но не содержат `download`.
**Решение:** `systems`, required и recommended dependencies хранятся в `ModuleTrack`. Для premium-пакета разрешено сохранять официальный versioned protected URL только как `sources.metadataManifestUrl`; копируемый `installManifestUrl` остаётся `null`.
**Альтернативы:** общие dependencies карточки отклонены как неточные; полный отказ от protected metadata отклонён, потому что он теряет официальное доказательство совместимости; публикация mutable или персональной premium-ссылки запрещена.
**Последствия:** прежняя формулировка о полном отсутствии premium manifest в локальной модели уточнена: внешний флаг `protected` не дублируется в production, но безопасный versioned metadata source хранится отдельно и никогда не участвует в copy/allowlist. Валидатор сравнивает relationships выбранного track.
**Источник:** S-08…S-11, особенно `docs/pipeline/spikes/11-hover-protected.md`.
