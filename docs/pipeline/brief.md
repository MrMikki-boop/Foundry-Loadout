# Project Brief: Foundry Loadout

## Суть

Foundry Loadout — рабочее название независимого публичного справочника manifest-ссылок для ведущих, использующих Foundry VTT 13 или 14. Сайт помогает выбрать версию Foundry VTT, найти модуль, понять его назначение, совместимость и зависимости, а затем скопировать ровно одну проверенную manifest-ссылку. Сайт ничего не устанавливает, не хранит пользовательские сборки и не принимает произвольные URL. Первая рабочая версия успешна, если этот путь полностью работает для трёх реальных модулей на мобильном и десктопном экране, с клавиатуры и с автоматической проверкой данных.

## Пользователь и сценарий

Основной пользователь — ведущий Foundry VTT, который вручную устанавливает и обновляет модули через экран «Дополнения → Установить модуль». Он приходит на сайт перед настройкой сервера или мира, выбирает Foundry VTT 13 либо 14, находит подходящий модуль, сверяет зависимости и копирует одну ссылку в поле Manifest URL внутри Foundry VTT.

## Скоуп

**В скоупе MVP:** статический публичный каталог; отдельные ветки данных для Foundry VTT 13 и 14; поиск и фильтры; карточки модулей; статусы проверки; зависимости; видимый HTTPS manifest URL; копирование одной ссылки; понятный fallback при недоступном Clipboard API; инструкция по ручной установке; адаптивность и клавиатурная навигация; build-time/CI-валидатор allowlist-ссылок; три подтверждённых модуля в вертикальном срезе.

**Вне скоупа:** автоматическая и массовая установка; очередь, корзина или сборщик; «скопировать все»; отметки установки; общий meta-manifest; модуль-установщик; зеркала архивов; активация модулей; аккаунты; облачная синхронизация; ввод и загрузка URL посетителем; публикация персональных premium-ссылок; серверный proxy; полное наполнение каталога до утверждения вертикального среза.

## Стек и окружение

- Статический сайт без базы данных, авторизации и серверного API.
- UI собирается через Sites/Vinext и экспортируется в `out/` для GitHub Pages.
- Типизированный каталог с одной записью модуля и несколькими ветками совместимости.
- Клиентские поиск, фильтрация и копирование.
- Отдельный Node.js build-time/CI-валидатор внешних manifest URL.
- Локальная среда: Windows, Node.js 22.20.0, npm 10.9.3, Git 2.45.1.
- Публикация выполняется GitHub Actions из ветки `master`; Pages получает только статический артефакт.

## Как запускать

1. Установить зависимости: `npm ci`.
2. Запустить локальный сайт: `npm run dev`.
3. Открыть `http://localhost:3000/`.
4. Выполнить все локальные проверки и собрать Pages-артефакт: `npm run check`.
5. Проверить восемь внешних manifest: `npm run validate:data`. Команде нужен доступ к сети.
6. При необходимости открыть статический результат: `npm run preview:pages`, затем `http://127.0.0.1:4174/Foundry-Loadout/`.

На Windows перед `npm run check` нужно остановить запущенный dev/preview-процесс, если он держит `dist/client`: в текущей рабочей папке такой lock дал `EBUSY`, тогда как тот же проект в чистой копии прошёл полный check.

Рабочий экран содержит четыре проверенных модуля и одну premium-карточку, отдельные ветки V13/V14, поиск, фильтры, видимый Manifest URL, копирование одной ссылки и инструкцию ручной установки. Локальная база, переменные окружения и секреты не нужны.

## Статус после аудита

- Чистая сборка проходит lint, TypeScript, 5 тестов каталога, Pages build и 6 тестов rendered/export; восемь публичных manifest проходят живой валидатор.
- Полный интерактивный сценарий ещё не подтверждён встроенным Browser: подключение остановилось на ошибке trusted RPC path. Переключение версий, Clipboard success/fallback, клавиатура, масштаб и мобильный overflow остаются обязательной ручной проверкой.
- Сетевой валидатор использует редакционную allowlist и блокирует основные private/special-use сети, но denylist reserved IPv4 пока неполон. До релиза нужны исправление и негативные тесты security-инвариантов.
- Публичные сигнатуры в `contracts.md` и фактические внутренние функции расходятся; это нужно либо реализовать, либо сузить контракт до реального API.
- Проект ещё не добавлен в Git history, поэтому подготовленные CI и Pages workflow на GitHub не запускались.

## Ограничения и риски

- **Совместимость нельзя выводить из названия, даты или README.** Для каждой ветки нужны официальный manifest, официальный релиз и запись каталога Foundry VTT; `verified` — рекомендация автора, а `minimum` и `maximum` жёстко ограничивают установку.
- **`latest` изменяем.** Ссылка, подходящая V13 сегодня, может начать отдавать релиз только для V14. Ветка V13 должна быть закреплена на последней реально совместимой версии либо повторно проверяться перед каждой публикацией.
- **V13 и V14 нельзя смешивать.** Одна карточка хранит несколько `tracks`, но интерфейс показывает только ветку выбранной major-версии.
- **Premium manifest может быть персональным.** Токенизированные, подписочные и приватные URL не публикуются; карточка ведёт на официальную страницу покупки и получает отдельный статус.
- **Автоматический валидатор обращается к внешним URL.** Только редакционная allowlist-база, HTTPS, запрет localhost/private IP/metadata endpoints, тайм-аут, лимит размера, лимит редиректов, проверка Content-Type и конечного адреса снижают риск SSRF и зависания CI.
- **Clipboard API может отсутствовать или требовать защищённый контекст.** URL остаётся видимым и выделяемым; ошибка копирования не скрывается.
- **Данные быстро устаревают.** Каждая ветка хранит дату проверки и статус; публикация блокируется при ошибке обязательной проверки.
- **Рабочее название конфликтует с рекомендациями бренда.** Foundry Gaming LLC просит не сокращать Foundry Virtual Tabletop до «Foundry» и избегать официально звучащих названий. До релиза нужно либо согласовать нейтральное имя, либо получить письменное разрешение; на сайте в любом случае нужна явная пометка о неофициальном проекте.
- **Нельзя создавать впечатление одобрения Foundry Gaming LLC.** Не используем основной логотип как знак проверки и не заявляем, что каталог официально сертифицирован.
- **Нет 21st.dev.** Компоненты будут собраны штатными средствами выбранного стека по единой дизайн-системе; это влияет на источник паттернов, но не на функциональность.

## Глоссарий

- **Manifest URL** — прямая HTTPS-ссылка на корректный `module.json`, который Foundry VTT использует для установки пакета.
- **Track** — версия manifest и метаданных одного модуля для конкретной major-версии Foundry VTT.
- **Проверено** — URL доступен, ответ является допустимым JSON, идентификатор и версия согласованы с релизом, а заявленный диапазон включает выбранную версию Foundry VTT.
